================================================================================
                 ROHAFYA SaaS — DOSSIER DE DOCUMENTATION FONCTIONNELLE
================================================================================

ROHAFYA accueille plusieurs établissements de santé. Chaque personne a UN compte,
identifié par son adresse e-mail, et retrouve dans ce compte les données de tous
les établissements auxquels son dossier est rattaché.

Ce dossier complète « Documentation/ » (versionnage et déploiement). La mise en
service technique du mode SaaS côté API est décrite dans le dépôt de l'API
Rohafya : Rohafya/saas/README.md.


CONTENU
-------
  connexion/                      Comment se connecter : un fichier par rôle
    01_SUPER_ADMINISTRATEUR.txt     contrôle toute la plateforme
    02_ADMINISTRATEUR_ETABLISSEMENT.txt  gère un établissement et ses patients
    03_PATIENT.txt                  consulte ses résultats et factures
    04_MEDECIN.txt                  reçoit les résultats partagés par ses patients
    05_LOGICIEL_ETABLISSEMENT.txt   le logiciel qui envoie les données (clé d'API)

  donnees-test/                   Jeux de données pour essayer les imports

    import-rohafya/                 import au format ROHAFYA (API /ingest/v1)
    import-fhir/                    import au standard HL7 FHIR R4 (API /fhir/r4)
    importer-rohafya.sh             envoie le jeu ROHAFYA avec curl
    importer-fhir.sh                envoie le jeu FHIR avec curl

  extraction-pdf/
    EXTRACTION_RESULTATS_PDF.txt    extraire les résultats d'un PDF de laboratoire,
                                    y compris quand la mise en page change


LES CINQ RÔLES EN UN COUP D'ŒIL
-------------------------------
  Rôle                          Adresse              Se connecte avec
  ────────────────────────────  ───────────────────  ──────────────────────────
  Super-administrateur          /super-admin         code reçu par e-mail
  Administrateur d'établissement /admin              code reçu par e-mail
  Patient                       /patients            code e-mail, ou identifiant
                                                     + mot de passe (historique)
  Médecin                       /doctors             code e-mail, ou identifiant
                                                     + mot de passe (historique)
  Logiciel de l'établissement   /ingest, /fhir       clé d'API (en-tête HTTP)

Rôles techniques (table « roles » de l'API) et ce qui les donne :
  SuperAdmin (ou l'historique Admin)   flask saas create-superadmin
  EstablishmentAdmin                   ajout comme administrateur d'un
                                       établissement (aucune permission à cocher)
  Patient                              création du compte ; permissions patients.*
  Doctor                               import du médecin ; permissions doctors.*
Les permissions des rôles Patient et Doctor sont attribuées par
« flask saas init » (à relancer après chaque mise à jour de l'API).

Après connexion, ROHAFYA ouvre automatiquement l'espace correspondant au rôle.


PRESCRIPTIONS, PRÉ-ENREGISTREMENTS ET REQUÊTES : QUI ENVOIE, QUI RÉPOND
----------------------------------------------------------------------
  Envoient       patients (/patients), médecins (/doctors), visiteurs sans
                 compte (requêtes seulement, /requests)
  À qui          UN établissement actif, choisi dans le formulaire
  Répondent      les administrateurs de cet établissement : /admin/demandes
                 (statut, message, montant du devis)
  Suivi          l'auteur voit statut et réponse dans son espace, et reçoit une
                 notification et un e-mail (le visiteur : e-mail seulement)
Détails : connexion/02 (section 4 ter), 03 (5 bis) et 04 (5 bis).
Adresse de production utilisée dans ces documents : https://rohafya.com
(remplacez-la par l'adresse de préproduction pour vos essais).
